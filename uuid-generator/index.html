What Is a UUID?

A UUID (Universally Unique Identifier) is a 128-bit identifier formatted as 32 hexadecimal digits in five groups separated by hyphens: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx. UUIDs are designed to be unique without requiring a central authority to assign them.

UUID Versions

Version 4 (Random)

The most common version. Uses random or pseudo-random numbers. 122 of the 128 bits are random, giving 2^122 possible values. Collision probability is effectively zero. This is what most applications use and what this tool generates.

Version 1 (Time-based)

Combines the current timestamp with the MAC address of the generating machine. Predictable, so not recommended for security-sensitive use. Useful when you need UUIDs that sort by creation time.

Version 7 (Time-ordered)

Newer standard (RFC 9562). Combines time and randomness in a way that sorts chronologically. Better for database primary keys because they're sequential and index-friendly.

Frequently Asked Questions

Can two UUIDs collide?

In practice, no. You would need to generate about 2.7 × 10^18 UUID v4 values before a 50% chance of any collision exists. At one billion UUIDs per second, that would take about 85 years.

Are UUIDs secure?

Version 4 UUIDs generated with crypto.randomUUID() are cryptographically random and safe for security purposes. UUIDs generated with non-crypto random sources are not.

Should I use UUIDs as database primary keys?

Version 4 UUIDs are not sequential, which hurts database index performance. Use UUID v7 for primary keys — they're time-ordered and index-friendly. For internal use, consider sequential IDs like auto-increment integers.

Do you store my UUIDs?

No. Generation happens entirely in your browser. Nothing is sent to our servers.
