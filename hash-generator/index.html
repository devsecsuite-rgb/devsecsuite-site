What Is a Hash Function?

A hash function takes an input of any size and produces a fixed-size output called a "hash" or "digest." The same input always produces the same hash. Different inputs almost always produce different hashes. Hashes are one-way — you can't reverse them to recover the original input.

Hash Algorithms Compared

MD5 (128-bit)

Fast but cryptographically broken. Collisions can be generated in seconds. Still used for non-security checksums and legacy systems. Do not use for passwords or signatures.

SHA-1 (160-bit)

Also broken. Google demonstrated a practical collision in 2017. Deprecated for security use but still common in git and older systems.

SHA-256 (256-bit)

Part of the SHA-2 family. Currently considered secure. Standard for TLS certificates, blockchain, and password hashing (with salt and iterations).

SHA-512 (512-bit)

Larger variant of SHA-2. Slower than SHA-256 but more secure against brute force. Used in high-security contexts.

Frequently Asked Questions

Can I reverse a hash?

No. Hashing is one-way by design. However, weak inputs (like common passwords) can be looked up in "rainbow tables" of precomputed hashes. Always use a salt and a slow algorithm like bcrypt or Argon2 for passwords.

What's the difference between hashing and encryption?

Encryption is reversible with the right key. Hashing is not reversible. Use encryption when you need to recover the original data; use hashing when you only need to verify integrity.

Which hash should I use?

For checksums: SHA-256. For passwords: bcrypt or Argon2 (not plain SHA). For digital signatures: SHA-256 or SHA-512. For legacy compatibility: MD5 or SHA-1, but only if you must.

Do you store my data?

No. Everything runs in your browser using the Web Crypto API. Nothing is sent to our servers.
